# Collaudo di Oblivion 1.0

La [roadmap](oblivion1.0-roadmap.md) descrive cosa entra nella 1.0. Questa lista specifica come verificarlo. Il [registro tecnico](STATUS.md) conserva le prove precedenti su codice, fixture e VM.

Le prove **Browser** usano il binario Oblivion installato e le TUI native dentro un terminale del browser collegato al runtime reale. Le prove **Desktop**, **CLI**, **Lab** e **Live** richiedono le superfici indicate nella tabella. Un esito vale per il flusso, la build e la piattaforma registrati.

Per ogni prova annotare ID, data, build, piattaforma, superficie, esito (`Pass`, `Parziale`, `Fallito`, `Bloccato`), risultato osservato ed eventuale riferimento al commit della correzione. Le righe senza un esito nel registro restano da eseguire per la candidata. Dopo un fix, ripetere il caso sulla nuova build e aggiungere un esito.

Usare archivi e dischi separati dai dati personali, file sintetici e due runtime distinti per i ripristini. Eseguire crash, saturazione, interruzioni e `runtime atomic` solo in ambienti di test dedicati. Inserire le credenziali di prova nel client nativo quando richiesto e tenere password, token, codici di accesso e contenuti reali fuori da evidenze, log e commit.

## Prerequisiti aperti

- Per le prove persistenti Mac serve inizializzare l'archivio QA dal prompt locale, quindi predisporre le password delle Safes e un secondo archivio QA indipendente per FAM-01, BAK-01/02 e SHARE-01/02. Il collaudo dei login salvati richiede almeno una chat sintetica autenticata nel volume di origine.
- Per AG-03/04 e la delega servono account o chiavi di test nei client nativi. Codex richiede Device Code abilitato o la forma API prevista dal test. Claude Code richiede un account di prova o la forma API prevista. OpenCode 2 richiede una chiave `abliteration-ai`. Per la delega verificare una forma esplicitamente supportata per ciascun agent. La sola apertura del menu non qualifica login, streaming, scadenza o persistenza.
- Per NET-02/03/04 servono un endpoint SOCKS5 pubblico controllabile con autenticazione, un endpoint di prova TCP/FTP passivo e redirect, una regola positiva Strict e la possibilità di fermare il proxy a richiesta. Per SHARE-03 serve un destinatario OnionShare indipendente su Tor pubblico.
- Per FILE-05 e le scorciatoie desktop serve accesso alla finestra AppKit e a un terminale nativo. Per PLAT-02 servono host Linux amd64 e arm64 con KVM e virtualizzazione annidata. Per PLAT-03 serve Windows x64 con Hyper-V e account separati per UAC e ACL. Per PLAT-04 e FILE-06 servono macchine amd64 e arm64 compatibili e supporti USB sacrificabili per boot, backing e trasferimenti. Sul Mac di prova non è collegato un supporto USB esterno.
